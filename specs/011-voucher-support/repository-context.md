# Voucher baseline review — 2026-11-20

Read-only review for specification; this document reports baseline behavior, not implemented Voucher support.

- Constitution: domain-owned repositories and acyclic service dependencies; prepared DTOs/pure converters, dedicated validators, strict ownership and safe ProblemDetail; exact timestamps, additive migrations, domain/layer tests and real commit/concurrency verification. No Constitution amendment or new dependency is implied.
- Cart: specs/007-shopping-cart/spec.md and feature010 follow-up; CartResponse/PreparedCart, CartCalculator and CartTransactionServiceImpl use selected fully eligible row subtotal with exact whole-VND arithmetic. finalTotal currently equals selectedSubtotal. Existing add/quantity/variant/individual/bulk selection semantics and missing-cart lazy creation must remain. Vouchers do not currently exist.
- Catalog: ProductCatalogServiceImpl and CatalogCartReadServiceImpl prepare current publication-safe prices and batched Inventory availability. Out-of-stock published metadata remains visible; no stock filter/ranking change. These observations determine preview eligibility, not a promise of checkout availability.
- Inventory: specs/010-inventory-management/spec.md; InventoryService defines observe/lock/reserve/release/consume. Checkout reserves exact created items (reserved only); managed first cancellation releases reserved; guarded internal completion subtracts both stock/reserved. FAILED processing, admin supply, public confirmation, payment/expiry producers remain deferred.
- Checkout: specs/009-customer-checkout/spec.md, CheckoutServiceImpl and CheckoutValidator. Receipt-first lookup precedes concurrency fence; fresh acquired/busy lookup protects completed replay. Fingerprint is address-only checkout:v1:addressId=…; receipt hits never read mutable cart state. New work coordinates user/cart/catalog, classifies stock last, creates one order, reserves Inventory, consumes included rows and writes immutable receipt atomically. Successful response201/Location is unchanged on replay. Current request contains only addressId; the proposed voucher comes from first-execution cart state.
- Order: specs/008-customer-order-management/spec.md and OrderServiceImpl/OrderCompletionServiceImpl. Cancellation only PENDING/CONFIRMED, valid CANCELLED repeat204 before Clock/Inventory; SHIPPING/COMPLETED/FAILED reject cancellation. History snapshots and payable sorting are existing contracts. Merchandise and payable fields currently have no voucher discount explanation; item sum integrity must remain when a new order-level discount is introduced.
- Existing schema/receipts: V23 order amounts are nonnegative integral NUMERIC; V24 receipt validator/codec and V25's narrow extension recognize the existing immutable structure. Voucher planning must add compatible integrity/representation support without editing older applied migrations or rewriting historical receipts. Do not assume old receipt decoders accept new fields.
- Authentication: AuthSecurityConfiguration uses current Bearer state and exact MANAGE_CART, MANAGE_CHECKOUT, MANAGE_ORDER route permissions. No voucher routes/grants are present. Owned wallet authentication and future exact permission mapping must not accidentally require MANAGE_CART for an otherwise authorized checkout replay.
- Repository source search found no Voucher or payment implementation to reuse. Voucher ownership is administrator-granted under the approved custom policy. No admin API exists or is added; tests will prepare explicit grants.
- Approved follow-up: own wallet entitlements replace public discovery/code application; one-use grants permit explicit remaining entitlements under definition-level global/personal limits. Successful cart evaluation clears invalid selections; checkout independently rejects invalid selections. Voucher cancellation policy is deferred despite existing Order cancellation; do not remove or extend that baseline. No plan/tasks/data-model artifacts exist yet; later stages must carry these rules forward.
- Active spec-template resolved through .specify/scripts/powershell/resolve-template.ps1; sequential numbering selects011. Actual branch remains feature/cart; existing uncommitted Inventory work is preserved. Before-specify extensions.yml absent. No application command, migration or test was executed for this new specification.
