# Research — UC-037

| Decision | Rationale and evidence | Alternatives considered |
| --- | --- | --- |
| Extend existing Inventory balance | V25 uses one live/original Variant UUID and deferred ACTIVE reconciliation. Existing Inventory repository supplies fresh ordered row locks. | Separate balances or writing reserved would split authority or violate V25. |
| Journal provides replay | Exact typed payload and versioned event result permit replay without a second durable table. Checkout demonstrates successful-result recovery before mutable checks. | Volatile cache or retrying a delta cannot guarantee durable outcomes. A pending-claim table adds recovery states. |
| Scoped transaction fence plus database uniqueness | Reuse Checkout's two-read pattern. PostgreSQL's two-int advisory key space is separate from Checkout's one-BIGINT key space. Use a fixed Inventory namespace and deterministic hash of actor and UUID. Only full DB keys and typed fields define identity. | Unique constraint alone would abort a duplicate at insert and could let mutable-state rejection preempt replay. Row-level fence table adds persistence and retention. |
| Protect Product, Variant, balance in order | Checkout protects Catalog before balance. Catalog claims Product before child writes. Terminal Orders lock Order before balance and never require a Catalog lock for Inventory resolution. | Balance-first could invert Checkout. A version without lifecycle protection can admit a write after Archive. |
| Exact decimal-string API quantities | Signed BIGINT exceeds JavaScript safe integer range. Admin Catalog already uses decimal strings for BIGINT revision values. | JSON numeric quantities risk client rounding. A lower cap violates BR-I02. |
| Variant-first reads and retained history | A left join preserves live records missing a balance. Original UUID and journal index keep history independent of saleability. Use bounded scalar projections. | Reusing Catalog aggregate SKU search would return unrelated siblings. Loading entities per row creates N+1. |
| Additive migration | Source migration head is V28. Journal is empty at rollout and does not rewrite protected data. | Filling synthetic events or changing V25/V28 would alter provenance or upgrade history. |
