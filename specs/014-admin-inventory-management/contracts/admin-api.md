# Admin Inventory API — planned contract

Base `/api/admin/inventory`. All routes require authenticated current ROLE_ADMIN and ACTIVE account. Current Jwt identity supplies adminId. Existing bearer security responses apply before body validation, history lookup, or replay.

| Method and path | Request | Success |
| --- | --- | --- |
| GET `/variants` | optional `q`, repeated Product `status`, `page`, `size` | 200 page of variant records |
| GET `/variants/{variantId}` | UUID | 200 variant record |
| GET `/variants/{variantId}/history` | UUID, optional `page`, `size` | 200 journal page |
| POST `/variants/{variantId}/replenishments` | JSON `operationId`, `delta`, optional `reason` | 200 immutable operation result |
| POST `/variants/{variantId}/corrections` | JSON `operationId`, `delta`, required `reason` | 200 immutable operation result |

Variant record includes variantId, productId, productName, sku, productStatus, variantEnabled, catalogSaleEligible, onHand, reserved, available and stockStatus. Catalog sale eligibility uses existing Catalog publication/enabled/sale validity independently of numeric availability. Stock status is OUT_OF_STOCK for known zero, IN_STOCK for positive available, UNAVAILABLE for absent live balance. Return all three counts as null when unavailable. Include Archived and Disabled by default. Detached records appear through history, which can resolve a UUID with retained events even when current detail returns 404. Live variants with no journal return an empty page. Unknown history identity with neither a live variant nor retained events returns 404.

Page envelope follows `items,page,size,totalItems,totalPages`. Default page 0 and size 20, maximum size 100. Escape wildcard metacharacters and bind case-insensitive literal substring searches of Product name or the specific Variant SKU. Order list by Product display name then Variant UUID ascending. Order history by occurredAt then journal ID descending. Out-of-range valid pages are empty with correct totals. Counts and rows use one statement snapshot or equivalent coherent projection. Separate requests may see changed data.

Operation result and history item expose operationId, variantId, adminId, operationType, delta, onHandBefore, onHandAfter, reservedObserved, availableAfter, reason and occurredAt. No mutable Catalog fields. Signed BIGINT quantities and actor IDs travel as exact base-10 strings. Delta accepts whole-integer decimal strings (optional minus and canonical digits after parsing), with semantic checks on zero, sign and bounds. Reasons trim Unicode whitespace at both ends, preserve interior text and validate length after trimming. Whitespace-only and absent optional reasons canonicalize to null. Compare typed UUIDs/numbers and normalized reason. Replay returns the same status and body values after later writes or archive.

Use current problem-response conventions and stable codes. 400 for invalid UUID, malformed JSON, invalid field shape or pagination. 415 for unsupported body media type. 422 for invalid whole-unit input, sign, zero, precision/bounds or reason. 404 for unknown live mutation/detail target or unknown history identity. 409 for Archived parent, required balance missing, reservation floor, payload conflict, or retryable operation/lock contention. Only the authorized floor conflict includes onHand, reserved and available observed under protection. For a representable negative correction crossing the reserved floor (including crossing zero), floor 409 takes precedence over result range. Mismatched replay gives no historical response or unrelated identifiers. Unexpected persistence and integrity faults fail safely without leaking SQL, reasons or cross-account data. A malformed request has no replay side effects.

## Exact validation and error precedence

Use a strict JSON object and strict string tokens for delta, operation UUID and supplied reason. Omitted optional replenishment reason is allowed; explicit null is an invalid shape. Reject unknown/duplicate properties and missing required fields with 400 `INVENTORY_INVALID_REQUEST`; malformed JSON, invalid UUID, numeric JSON tokens (integral or fractional), wrong types and invalid pagination also return this code. Unknown properties include absolute SET fields. For a delta string, accept only ASCII `0|-?[1-9][0-9]*` without trimming. Empty, whitespace, fractional, nonnumeric, noncanonical or overlong strings and signed overflow/underflow return 422 `INVENTORY_INVALID_QUANTITY`. Bound token length before parsing. Zero is invalid for both actions; a negative replenishment is invalid. Positive 1 and MAX are valid inputs subject to the resulting stock limit. Negative 1 and MIN are representable correction inputs; compare a signed delta directly with `reserved-stock` and `MAX-stock` without abs/negation. MIN necessarily crosses the floor and returns its 409 for an eligible existing balance. Missing correction reason is 400; a supplied blank or overlong normalized reason returns 422 `INVENTORY_INVALID_REASON`. Normalize Unicode White_Space at the edges, count Unicode code points after trimming and preserve interior text; optional blank and omitted reasons canonicalize identically.

Authorization runs first using existing 401/403 handlers, then media/shape (415 `INVENTORY_UNSUPPORTED_MEDIA_TYPE`, 400), immutable semantic validation (422), authorized exact-key replay or contention, then fresh target and balance checks. Use 404 `INVENTORY_NOT_FOUND`; 409 `INVENTORY_ARCHIVED`, `INVENTORY_BALANCE_UNAVAILABLE`, `INVENTORY_RESERVATION_FLOOR`, `INVENTORY_OPERATION_CONFLICT` for changed payload and `INVENTORY_CONCURRENT_CONFLICT` for retryable contention. A representable reduction below zero still uses the floor code. Only the floor problem carries target onHand, reserved and available as exact decimal strings. Use existing safe 500 handling for unexpected failures. Retained history remains accessible by original UUID.

## Read snapshot and security wiring

Use one statement per list/history response with a shared filtered relation, total row and paged projection left-joined to that total. Carry history identity existence in the same snapshot so known-empty history differs from 404. An empty page still returns its total. Detail is one scalar statement. Different HTTP requests may see different data. Verify pages and totals across concurrent commits without promising a frozen multi-request snapshot.

Select Inventory in the existing order-2 chain via its base and subtree matchers, add only the five authorized method/path patterns before deny-all and align the bearer CSRF ignore list with those paths. Preserve Catalog matchers, current-state JWT converter and existing auth/problem handlers. Confirm behavior with bearer HTTP, including wrong method/path denial. C01 stays an inherited production gate and SharedCorsConfiguration stays out of scope.
