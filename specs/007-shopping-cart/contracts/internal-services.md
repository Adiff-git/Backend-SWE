# Cart internal service contract

Updated 2026-11-17. All types are under com.example.demo. Public facade methods are getCart(owner), addItem(owner,AddCartItemRequest), updateQuantity(owner,itemId,UpdateCartQuantityRequest), changeVariant(owner,itemId,ChangeCartVariantRequest), removeItem(owner,itemId), selectItem(owner,itemId,CartSelectionRequest) and selectAll(owner,CartSelectionRequest). Response-bearing transaction methods additionally take nullable PreparedImageUrls; remove returns void. Add returns internal AddCartResult; controller exposes only CartResponse and always HTTP 200.

Facade validates shape/positive owner and performs owned non-authoritative preflight before any target image preparation. Unknown/foreign sources fail safely before target metadata. Call ImageUrlResolver.prepare outside authoritative transactions only if image candidates exist. Never reuse writable managed preflight entities. Transaction service repeats ownership/business checks under common parent lock and reads children fresh after coordination.

Write protocol: transaction-local positive lock timeout BEFORE first cart lock; if missing add, existing UserService user-lock protocol then timeout/recheck/cart creation; never Cart to User lock order. READ_COMMITTED/REQUIRED. Quantity update validates retained current variant and replaces quantity only. Variant change validates current target/same product; current target no-op, absent target source quantity=1 plus public target snapshots, existing target source deletion only with target untouched. Source selection/time persist unless the source is deleted. Final target presentation/eligibility, calculations and flush happen before commit. Signing failure rolls back even after source deletion or quantity flush. No broad retry or postcommit mandatory fallible work.

CartValidator owns quantities, final added sum, owned lookup, same-product and eligibility/selection. CartCalculator computes exact whole-VND amounts and checked aggregate Long values once. CartConverter maps prepared values and safe snapshots without fetching/signing or duplicate arithmetic. CartReadSeed/PreparedCart/AddCartResult stay immutable defensive Lombok @Value DTO classes in cart/dto/response.

CatalogCartReadService owns scalar batched variant state, image-candidate preflight and final presentation. Batches are 100 internally, with no cart row cap. Order image product locks globally by canonical UUID string (PostgreSQL order), ORDER BY id in each lock query. Reflect final publication state consistently in flags/totals. Hidden descriptions/images never leak; new image without a prepared capability may be null. Real prepare/sign failures are not suppressed. PreparedImageUrls owns no request resource; no cart cleanup/close lifecycle exists.

GET is business-nonmutating but write-capable for publication FOR SHARE; it inserts no cart or snapshot/selection updates. Safe persistence error mapping occurs after failed transaction rollback. Existing authorization/session and ProblemDetail mechanisms remain unchanged.
