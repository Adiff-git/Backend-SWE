# Migration verification and recovery

New V16 matcher/protection,V17 conservative typo guard,V18 fast/safe normalization,V19 generated description token cache. V1–V15 file hashes unchanged. Fresh install and V15 upgrades are executed only in disposable PostgreSQL. Direct V14→V19 and V15→V19 proofs executed;historical V14→V15 proof retained. Original business fields are byte-equivalent before/after upgrade;only the explicitly new derived cache column is excluded from old-field snapshots and separately checked for exact backfill/update/malformed-field behavior.

Missing pg_trgm package/installation privilege/pinned collation blocks migration with rollback. Runtime capability loss returns503 and unhealthy readiness in enabled/disabled modes;healthy probe recovers. V20 is an ephemeral test successor,not an application migration:its transactional failure preserves the successful V19 prefix,rolls back successor objects/history,and succeeds when the external transient condition is fixed using the identical artifact. A mismatched checksum triggers STOP;no repair/clean/baseline/history edits are used.

On a real failure:stop rollout,inspect latest successful installed_rank and Flyway validate,compare approved hashes and failed transaction/object state. Retry the identical artifact only for a verified transient cause after recovery approval. A defective immutable predecessor/checksum mismatch requires reviewed restore or a new corrective migration;do not edit applied files,skip versions or repair history. V19 backfill takes a table lock and adds write/storage work;target duration/recovery/privileges remain deployment verification,not inferred from tests. No shared/prod migration was run.
