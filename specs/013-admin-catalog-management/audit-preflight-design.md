## V27 entry point and preparation

T081 prepares a shared, entity-independent persisted-fact validator and read-only applicability projection before T008. T008 then implements the proposed plain Java `com.example.demo.catalog.audit.CatalogCompatibilityAudit` entry point under `demo/src/main/java/com/example/demo/catalog/audit/`. This is an operator CLI, not an HTTP endpoint, Spring service or a second catalog application. Its main method must not call SpringApplication, create an ApplicationContext, use a Spring repository/EntityManager, initialize Flyway, or start cleanup/scheduling. It uses ordinary JDBC and the already approved dependencies. Loading dependency classes on a classpath is not authorization to start their auto-configuration.

The future invocation is `java -cp "$AUDIT_CLASSPATH" com.example.demo.catalog.audit.CatalogCompatibilityAudit`, using compiled classes and the existing resolved runtime dependency jars. T008 must document how its exact classpath is assembled with existing tooling; no new build plugin or dependency is authorized. Connection URL/user/password are privately supplied as `AUDIT_JDBC_URL`, `AUDIT_DB_USER`, `AUDIT_DB_PASSWORD`; no values are logged or committed. The CLI requires an explicit expected database identity and V27 migration/checksum manifest supplied by the operator, rejects a different schema/history and never silently audits another target. A changed supported baseline needs explicit review, not a best-effort continuation.

Only SELECT projections of V27 columns are permitted: Product id/category/status/name, existing variant SKU/price/options/technical_specifications, Category identity/name/parent, Brand identity/name/code, and existing image metadata/source relations. It must not select `version`, `enabled`, `active`, `last_restored_at` or `catalog_taxonomy_state`. V27 variants/images are evaluated as the proposed default Enabled/active for readiness reporting, without persisting those defaults. No new entity mapping is required even after T015 is implemented.

Use a restricted read-only database account, a JDBC connection configured read-only with autocommit disabled, and REPEATABLE READ (the same justified audit snapshot as the approved SQL). Verify transaction_read_only before reading; apply bounded statement/lock timeouts. End with ROLLBACK on success, violations or failure. Reject write/repair/migrate modes and any schema-creation fallback. T086 must prove against a disposable V27 database that the CLI succeeds with only SELECT privileges, keeps schema/history/row fingerprints unchanged, and does not require the new migration even when newer migration resources are on the classpath. Permission, timeout, missing-column/function and capability errors mean INCOMPLETE/BLOCKED, never a clean audit.

A shape-only PASS is not applicability PASS.

## Read-only allocation supplement

[contracts/data-preflight-allocation-integrity.sql](contracts/data-preflight-allocation-integrity.sql) is a mandatory additional SELECT-only audit, not Flyway SQL or remediation. It extends the original V27 preflight's section 7 using `V25__inventory_management.sql::validate_inventory_order`, balance constraints and allocation domain resolution as evidence. Both scripts must run against the same identified target and immutable restored snapshot; if the live target changed, repeat the complete gate rather than combining unrelated snapshots.

All violation result sets must be empty. The supplement checks managed-order participation, item/allocation cardinality, quantity, state and lifecycle timestamps, retained/live variant attribution, terminal history shape, uniqueness and exact ACTIVE reservation totals. A legitimate null catalog reference on retained terminal history is allowed; ACTIVE allocations require a live matching variant. SQL proves current relational integrity, not the historical immutability of values; compare controlled pre/post rehearsal fingerprints as a separate obligation. No customer/receipt payload or object key is emitted.

T086 uses standalone JDBC/JUnit PostgreSQL Testcontainers audit ITs in catalog/audit (no Spring context/JPA entity validation). Disposable fixture setup may explicitly provision a schema pinned to V27 before invoking the auditor; the no-startup/no-write proof applies to the auditor invocation, not that controlled test setup. T086 must later parse/execute both scripts on PostgreSQL17 and exercise each violation reason with isolated synthetic snapshot relations, including missing allocations with reserved=0. Synthetic relations may model corrupt historical snapshots without disabling production constraints or weakening application guards. Confirm valid ACTIVE, RELEASED, CONSUMED and inventory-unmanaged legacy histories, including permitted retained null references. No test or SQL runs in this remediation invocation.
