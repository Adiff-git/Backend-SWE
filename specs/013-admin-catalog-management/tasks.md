**Tests**: explicitly required. Write meaningful tests before implementation; verify expected failure where practical, then run owning focused compilation/unit/MVC checks after changes. Unit tests never load context; MVC uses @WebMvcTest, repositories PostgreSQL @DataJpaTest, service/API/flow real @SpringBootTest; no test transaction may hide required commit. Test→service→HTTP ordering is explicit.
**Format**: `- [ ] Tnnn [P?] [USn?] deliverable — path; dependencies; execution class`.
**Paths**: repository-relative; Java file lists in one directory share that directory. Proposed new classes are deliverables, not claims they exist. Production service files use existing `catalog/service/` interface/Impl convention; media retains its existing impl package.

## Execution classes and gates

- **OFFLINE**: source/test/document construction and unit/MVC verification need no live target. Dependencies on other OFFLINE deliverables still apply. These tasks may proceed while live G1 is blocked; they do not prove DB behavior.
- **DB**: execution requires working disposable PostgreSQL17 and, where relevant, Docker/LocalStack/AI, current reports and committed outcomes. Every DB task can have offline test construction, but cannot close until its runtime proof passes.
- **G1**: exact authorized target schema/history/collation + BOTH read-only SQL scripts + complete V25 order/allocation integrity + T081/T008/T086-proven V27-safe typed-fact/applicability CLI + bounded object audit + reviewed incompatibility decision. Plan reported databases unreachable, Docker unavailable and no migration executed; those findings remain historical blockers until rechecked. Do not assume dataset clean from prior import reports.
- **G2**: T014 disposable fresh/V27-upgrade and representative-copy rehearsal/backup restore AND T088 distinct post-rehearsal integrity closure. Fixture classification/adaptation T082/T083 precedes checkpoint A. Negative fixtures deliberately fail; incompatible representative copies are classified/reviewed, never automatically repaired.
- **G3**: target migration/rollout may NOT proceed until fresh G1 and G2 pass, exact remediation (if needed) is explicitly approved/completed/rechecked, writers/readers are quiesced and rollout separately authorized. This backlog does not execute target migration or remediation. Offline migration preparation and disposable negative rehearsal do not waive G3.

Task IDs are stable identifiers, not sort keys: added T081–T088 are placed before their consumers in topological display order; T015 is moved before fixture conversion. Test-authoring tasks may prepare assertions before the component exists, but cannot claim successful compile/execution until their paired concrete component task completes; no placeholder controller is permitted.

Each dependency below is required; an omitted inter-story edge means prepared fixtures may be used, not that runtime verification can be skipped. Checkpoints are completion gates, not a blanket ban on independent offline development.
