## Classification and execution ownership

- **P — positive**: the business oracle remains valid. Its persisted setup must satisfy the schema at the migration version being tested. An object-only unit fixture need not pretend it was committed or publication-ready.
- **N — negative**: deliberately invalid input/final state; retain rejection and full rollback assertions. Make all unrelated preconditions valid so a different new constraint does not accidentally satisfy the test.
- **H — historical/compatibility**: preserve immutable snapshots, receipts, retained references and pinned old-schema outcomes. A historical zero price is not a current zero-price purchase.
- **C — conflicting expectation/setup**: change only the approved behavior delta, preserving the P/N/H oracle. This is not permission to disable constraints, accept bad Published state or rewrite historical values.

Classifications can coexist within a class. Method-level exceptions below take precedence over a class's general role. A P oracle with C setup is not a valid positive fixture until the owning conversion task has corrected and verified it.

## Rules for the remaining affected suites

The inventory below records baseline source touchpoints, including shared-fixture propagation. P/N/H labels describe the existing oracle, not an assertion that every current persisted fixture is publication-valid. For all current-schema persisted positives, T083/T084 must inspect the complete transaction: images must exist at the first successful Published commit. A later image insertion cannot rescue an earlier invalid commit.

- **Catalog read/search/API/performance**: P visibility/projection/count/query/rank/filter oracles and N invalid requests remain; apply explicit ready Published setup, retain Draft/Archived exclusions, and add Unpublished/Disabled/active-gallery behavior only through owning feature tasks. Preserve exact workload and query budgets. No universal image auto-insertion into image-count tests.
- **Cart/Checkout**: P/N retain preference fields, authoritative prices, stock/selection validation and partial eligibility; C zero-current-sale assertions convert; H replay remains independent of current eligibility. Recovery must use actual Admin commands after they exist, not solely raw status SQL as new integration proof.
- **Order/Inventory**: H/P/N remain; valid current referenced product setup changes only. Reservation owners, quantities, balances and terminal timestamps do not change as compensation for catalog edits.
- **Media/Review/Wishlist**: P/N/H ownership, upload states, access, retained membership/history and optional imagery remain. Product-consuming tests need ready catalog setup; pure uploader tests need no invented product/gallery. Active public membership and all-row reconciliation references have different scopes.
- **Unit factories/DTO/converter/calculator tests**: P/N isolated values remain valid for their declared responsibility. They do not establish commit, publication, security or runtime integration. Update new field defaults/signatures later in owning tasks; do not mechanically require a database or image in object factories.
